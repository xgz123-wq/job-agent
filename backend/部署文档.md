# 部署文档

> 通用部署指南，适用于任意基于本脚手架的项目。

## 一、环境要求

- Docker 24+
- Docker Compose v2
- 服务器开放端口：`NGINX_HTTP_PORT`（默认 8080）、`NGINX_HTTPS_PORT`（默认 8443）

## 二、配置 .env

```bash
cp .env.example .env
```

**生产环境必改项：**

| 变量 | 说明 |
|------|------|
| `ENV=production` | 切换生产环境 |
| `PROJECT_NAME` | 项目名，影响容器名/网络名 |
| `SECRET_KEY` | JWT 密钥，必须改为强随机值（生产环境启动时若仍为默认占位串会直接报错） |
| `CORS_ALLOWED_ORIGINS` | 跨域来源，逗号分隔，如 `https://a.com,https://b.com`（生产环境留空会报错） |
| `SERVER_NAME` | Nginx server_name，填实际域名 |
| `POSTGRES_USER/PASSWORD/DB` | 数据库账号密码 |
| `DEEPSEEK_API_KEY` | DeepSeek API Key |

## 三、部署方式

### 方式 A：本地构建（默认）

适合首次部署或无镜像仓库的场景。

```bash
docker compose -f docker-compose.yml up -d --build
```

### 方式 B：预构建镜像（生产推荐）

使用 CI 推送到镜像仓库的镜像，不本地构建。

```bash
# 在 .env 设置 IMAGE_TAG，例如：
# IMAGE_TAG=ghcr.io/your-org/your-app:latest

docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

`docker-compose.prod.yml` 会：
- 使用 `${IMAGE_TAG}` 镜像而非本地 build
- 禁用 docker 内 Nginx（改用系统 Nginx 反代）
- Redis 不暴露端口到主机
- Flower 仅绑定 127.0.0.1

### 方式 C：开发模式（热重载）

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

开发模式挂载 `./app` 到容器，代码修改即时生效；Nginx 默认不启动。

## 四、初始化

```bash
# 1. 执行数据库迁移
docker compose exec app alembic upgrade head

# 2. 初始化管理员（可选）
docker compose exec app python -m app.scripts.seed_admin

# 3. 健康检查
curl http://localhost:${NGINX_HTTP_PORT:-8080}/health
```

## 五、系统 Nginx 反代（生产推荐）

`docker-compose.prod.yml` 不启动 docker 内 Nginx，建议在宿主机用系统 Nginx 反代到 `${API_PORT}`。示例配置（放到 `/etc/nginx/sites-available/`）：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:8001;  # 替换为 ${API_PORT}
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式支持（AI 对话）
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

如需 HTTPS，用 certbot 申请证书：

```bash
sudo certbot --nginx -d your-domain.com
```

## 六、运维命令

```bash
# 查看服务状态
docker compose ps

# 查看日志
docker compose logs -f app
docker compose logs -f celery-worker

# 重启服务
docker compose restart app

# 滚动更新镜像
docker compose -f docker-compose.yml -f docker-compose.prod.yml pull
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d

# 数据库迁移
docker compose exec app alembic upgrade head
docker compose exec app alembic revision --autogenerate -m "add xxx table"

# 备份数据库
docker compose exec postgres pg_dump -U ${POSTGRES_USER} ${POSTGRES_DB} > backup.sql

# 恢复数据库
cat backup.sql | docker compose exec -T postgres psql -U ${POSTGRES_USER} ${POSTGRES_DB}

# 停止并清理
docker compose down
docker compose down -v  # 同时删除数据卷（谨慎！）
```

## 七、Flower 监控（可选）

```bash
docker compose --profile monitoring up -d flower
# 访问 http://localhost:${FLOWER_PORT:-5555}
```

## 八、故障排查

| 现象 | 排查 |
|------|------|
| app 容器启动失败 | `docker compose logs app`；常见原因：SECRET_KEY 未改、CORS 留空（生产）、PG/Redis 未就绪 |
| 容器间 DNS 不通 | 确认所有服务都挂了 `app-network` |
| Alembic 报无 migrations | 检查 `migrations/versions/` 是否有迁移文件 |
| Nginx 502 | app 未启动或 `API_PORT` 与 nginx 模板不一致 |
| SSE 流式卡顿 | 系统级 Nginx 需 `proxy_buffering off` |

## 九、端口参数化说明

所有端口通过 `.env` 参数化，主机端口与容器内端口分离：

- `POSTGRES_PORT` → 主机端口（容器内固定 5432）
- `REDIS_EXTERNAL_PORT` → 主机端口（容器内固定 6379）
- `REDIS_PORT` → 容器内端口（app 连接用，默认 6379）
- `NGINX_HTTP_PORT` / `NGINX_HTTPS_PORT` → Nginx 主机端口
- `API_PORT` → app 监听端口（容器内 + nginx proxy_pass）
- `FLOWER_PORT` → Flower 主机端口

修改端口只需改 `.env`，无需动 compose 文件。
