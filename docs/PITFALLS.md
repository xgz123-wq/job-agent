# 预想会遇到的问题

按出现的先后排。遇到了先来这里查，没有再对教练说「卡住了」。

## 起步

| 问题 | 对策 |
| --- | --- |
| CI 一上来就是红的 | 预期之内。脚手架有 4 个遗留问题，修好它是阶段 1 的第一个任务 |
| `docker compose up` 后接口容器不停重启 | 同上，先看 `docker compose logs app` 的最后几行 |
| 端口被占用 | 改 `backend/.env` 里对应的端口，脚手架的端口都是参数化的 |
| 装依赖很慢或失败 | 让教练换镜像源，这是杂务 |

## 后端

| 问题 | 对策 |
| --- | --- |
| 加了模型但数据库里没有表 | 没生成或没执行迁移。让教练带你走一遍 `alembic revision --autogenerate` 和 `alembic upgrade head` |
| 加了接口但访问是 404 | 没在 `app/route/router_registry.py` 登记 |
| 接口返回 401 | 请求没带令牌，或令牌过期。这是鉴权在正常工作 |
| 不知道代码该写在哪一层 | 碰 HTTP 的在 api，做判断和流程的在 services，定义表的在 models |
| worker 里连数据库报错 | 照 `app/schedule/jobs/demo.py` 的写法，worker 里要自己建引擎和会话 |

## 前端

| 问题 | 对策 |
| --- | --- |
| 完全没写过前端 | 正常。先让教练搭好骨架并写完登录页，你读懂后自己改目标列表页 |
| 浏览器报跨域错误 | 开发时用 Vite 的代理把 `/api` 转给后端；线上由 Caddy 分流，同一个域名下没有跨域 |
| 页面刷新后登录状态没了 | 令牌要存在浏览器里，并在启动时读回来 |
| 样式调半天 | 第一版不追求好看。Tailwind 写到能用就停 |
| SSE 在本地正常，上线后攒成一坨才出来 | 反向代理在缓冲。接口里要有 `X-Accel-Buffering: no`，Caddy 配置里要有立即刷新 |

## 部署

| 问题 | 对策 |
| --- | --- |
| 服务器买在哪 | 境内服务器绑定域名对外提供网站服务需要先备案，流程按周计。想当天上线，选香港或海外节点。买之前向服务商确认当前规定 |
| 买多大的 | 接口、数据库、Redis、worker、beat 一起跑，建议 2 核 4G 起。1G 内存大概率不够 |
| 浏览器打不开 | 依次查：域名解析生效了吗；服务器防火墙和云厂商安全组放行 80 和 443 了吗；Caddy 在跑吗 |
| 证书申请失败 | 多半是域名还没解析到这台机器，或 80 端口没放行 |
| 上线后接口报 500 | 看 `docker compose logs`。常见原因：没执行迁移、`.env` 少变量 |
| `.env` 怎么放到服务器 | 手动在服务器上创建，不经过 git。生产的 `SECRET_KEY` 必须换成随机长串，脚手架会强制检查 |
| 数据库端口暴露在公网 | 生产环境里数据库和 Redis 只让本机访问，不映射到公网 |
| 服务器上从哪访问模型 | 确认服务器所在地区能访问你选的模型服务。不能的话换模型，只改环境变量 |
| 怕把线上搞坏 | 上线前备份数据库，脚手架的部署文档里有命令。这是规范，不是多余 |

## 智能体

| 问题 | 对策 |
| --- | --- |
| 搜索结果质量差，报告没法看 | 先别调提示词。看 steps 表，确认是搜索词不好、读网页失败、还是汇总出错 |
| 绕圈子停不下来 | 最大步数和预算上限从阶段 2 就要有 |
| 一晚上烧掉很多 token | 定时目标没有新内容时不调模型；心跳用便宜的模型 |
| 网页读不到内容 | 很多网站需要浏览器渲染。先跳过并记日志 |
| 招聘网站抓不到 | 不抓。用搜索 API，或手动贴岗位链接 |
| 重启后同一步执行了两次 | 阶段 3 要解决的问题：步骤有唯一编号，执行前先查是否已完成 |

## 学习过程

| 问题 | 对策 |
| --- | --- |
| 新概念太多，一下记不住 | 不用记。每个概念只要求答出概念卡上的三个问题，用到时让教练带着看真实文件 |
| 教练一次写了太多代码 | 直接说「太多了，拆开」 |
| 读完就忘 | 每个任务做完说「讲一遍」。讲过的才算学过 |
| 想换技术栈或加新功能 | 记进 `docs/DECISIONS.md` 的待办。计划已冻结 |
| 某一步卡了很久 | 15 分钟规则：换路或缩小范围，先让最丑的版本跑通 |
| 隔了几天回来不知道做到哪 | 说「开始」，教练会读进度告诉你 |

## 面试

| 问题 | 对策 |
| --- | --- |
| 被问到没做的功能 | 如实说没做、为什么、如果做会怎么做 |
| 被问「是不是 AI 写的」 | 如实说。重点讲你做的判断：定位、设计、验收、部署、评测 |
| 项目还没做完就有面试 | 正常。讲到当前阶段，没做的讲设计方案。阶段 1 完成后就有线上地址可以展示 |
| 说 Muse 参照 OpenClaw 被质疑 | 这是媒体报道，不是 Meta 官方说法。说「据报道」，再讲你自己对比两者公开架构的结论 |
