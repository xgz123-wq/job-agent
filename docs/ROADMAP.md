# 路线

原则：先打通最薄的一条全链路并上线，再往上加智能体。每个阶段结束都有一个线上能看到的变化，和一段面试能讲的内容。

| 阶段 | 你的角色 | 做什么 | 完成标志 | 这时面试能讲什么 |
| --- | --- | --- | --- | --- |
| 0 定位与原型 | 产品经理、架构师 | 读对标资料、认识脚手架、确认原型 | 能讲清一个请求的全链路和整体架构 | 产品定位、对标分析、架构设计 |
| 1 全栈骨架上线 | 全栈工程师、运维 | 修脚手架、目标的增查、登录和列表页、部署 | 用域名打开，能登录、建目标；CI 绿 | 一个功能从数据库到页面的完整过程；怎么部署的 |
| 2 智能体最小闭环 | Agent 工程师 | worker 里跑循环、工具、实时步骤页、报告 | 建一个调研目标，网页实时看到每一步并出报告 | 智能体循环、工具调用、为什么用队列、SSE |
| 3 长程 | Agent 工程师 | 状态机、断点续跑、定时目标、邮件通知 | 重启 worker 后任务续跑；定时目标按时触发 | 状态机、幂等、心跳、通知门槛 |
| 4 刹车与记忆 | Agent 工程师、安全 | 审批闸门和审批页、审计日志、记忆页 | 注入攻击被拦下；改偏好后行为变化 | 权限分级、提示词注入、上下文管理 |
| 5 评测与交付 | 测试、项目负责人 | 评测集、README、演示视频、备份、模拟面试 | 能报出六个指标；别人 3 分钟看懂项目 | 评测方法、失败归因、迭代过程 |

任务书在 `coach/stages/`。

## 每个阶段内部的节奏

| 步骤 | 谁做 | 产出 |
| --- | --- | --- |
| 1 看资料 | 你 | 看完 `docs/RESOURCES.md` 里对应钩子的必看部分 |
| 2 写标准 | 你 | `coach/standards/` 里的一个文件 |
| 3 写设计说明 | 你 | `coach/designs/` 里的一个文件 |
| 4 写代码和测试 | 教练，判断函数归你 | 一个分支 |
| 5 审查 | 你 | PR 描述里的审查结论 |
| 6 验收、搞坏实验、讲一遍 | 你和教练 | 合并，更新进度 |

前三步是你建立判断的地方，第五步是你使用判断的地方。教练只在第四步主导。

## 为什么阶段 1 就部署

很多人把部署留到最后，结果卡在最后。第一周就把一个只会「登录、建目标」的空壳放到线上，之后每加一个功能都只是重复同一套上线动作。部署里的坑（域名、证书、端口、内存）越早踩越便宜。
