# PRD（第 2 版：全栈）

第 1 版把它定义成本地命令行工具。这一版的变化：它是一个部署上线的网页应用，建在你的 fastapi-scaffold 之上。智能体的七个模块设计不变，换了落脚的地方。

更详细的对标分析在 Claude 文档里：https://claude.ai/code/artifact/518219d8-9939-41e9-812c-07e4580f6f11
两份冲突时以这一份为准。

## 产品一句话

一个部署在自己服务器上的求职长程智能体。在网页上给它一个目标，它在后台拆步骤、持续执行、实时汇报，有结果主动通知，敏感操作等你在网页上批准。

## 两个目标，同等重要

1. **走通一次完整的全栈开发**：产品定位、原型、数据库、后端接口、前端页面、后台任务、部署上线、持续集成。
2. **掌握智能体的核心技术**：循环、工具、状态与恢复、调度、记忆、审批、评测。

衡量标准：线上有一个能访问的地址；每一层你都能讲清楚；自己求职时在用。

## 不做什么

- 支付、订票、代下单
- 原生手机 App（网页做成手机上也能看）
- 多租户、计费、管理后台的新功能
- 训练或微调模型
- 招聘网站爬虫
- 自动投递（必须人工批准）

## 对标 Muse：界面和能力各借什么

| Muse 的设计 | 本项目的对应 |
| --- | --- |
| 目标页：列出它在跟踪的所有目标和计划 | 目标列表页、目标详情页 |
| 活动日志：随时能看它做过什么 | 目标详情页里的实时步骤流 |
| 结构化审批卡片，不走对话 | 审批页，批准和拒绝两个按钮 |
| 记忆文件用户可读可改 | 记忆页 |
| 后台持续工作，App 关了也不停 | Celery worker 执行，状态存数据库 |
| 做完先判断值不值得打扰 | `should_notify`，邮件通知 |
| Sentinel：智能体只能提议 | 审批闸门，在循环之外 |

## 页面（详见 `docs/PROTOTYPE.md`）

1. 登录 / 注册
2. 目标列表
3. 目标详情：计划、实时步骤、产出报告
4. 审批
5. 记忆与偏好

## 选型（不在这张表里的，先不引入）

| 需要 | 选择 | 理由 |
| --- | --- | --- |
| 后端 | FastAPI，沿用脚手架 | 已有，结构规范 |
| 数据库 | PostgreSQL | 脚手架已有；任务状态要可靠持久化 |
| 缓存与队列 | Redis | 脚手架已有；给 Celery 当队列，给进度推送当通道 |
| 后台任务 | Celery worker + beat | 脚手架已有；智能体循环在 worker 里跑，beat 当心跳 |
| 实时推送 | SSE | 脚手架已有流式接口；单向推送够用，比 WebSocket 简单 |
| 前端 | React + TypeScript + Vite + Tailwind | 岗位需求最多；纯静态产物，部署简单 |
| 模型 | OpenAI 兼容接口，沿用脚手架的封装 | 换模型只改环境变量 |
| 部署 | 一台云服务器 + Docker Compose | 一条命令起全部服务，本地和线上同一套 |
| 入口与 HTTPS | Caddy | 自动申请和续期证书，配置几行 |
| 持续集成 | GitHub Actions | 推送后自动跑检查和测试 |
| 通知 | 邮件，沿用脚手架 | 不依赖任何聊天平台 |

## 数据模型

在脚手架已有的 `users` 之外，新增：

| 表 | 存什么 | 阶段 |
| --- | --- | --- |
| `goals` | 用户给的目标、状态、是否定时 | 1 |
| `tasks` | 目标拆出的任务、状态 | 2 |
| `steps` | 每一步：调了什么工具、参数、结果、token、时间 | 2 |
| `approvals` | 待审批的动作、裁决、裁决时间 | 4 |
| `audit_logs` | 每次提议和闸门的裁决 | 4 |
| `memories` | 身份层和长期记忆 | 4 |

## 接口草案

| 方法与路径 | 作用 | 阶段 |
| --- | --- | --- |
| `POST /api/v1/goals` | 新建目标 | 1 |
| `GET /api/v1/goals` | 我的目标列表 | 1 |
| `GET /api/v1/goals/{id}` | 目标详情：任务、步骤、报告 | 2 |
| `GET /api/v1/goals/{id}/events` | SSE：实时步骤 | 2 |
| `GET /api/v1/approvals` | 待我审批的动作 | 4 |
| `POST /api/v1/approvals/{id}/decision` | 批准或拒绝 | 4 |
| `GET` / `PUT /api/v1/memory` | 读写记忆 | 4 |

## 功能与验收

| 编号 | 功能 | 验收标准 | 阶段 |
| --- | --- | --- | --- |
| F0 | 全栈骨架上线 | 用域名通过 HTTPS 打开，注册、登录、新建目标，刷新后还在；CI 是绿的 | 1 |
| F1 | 公司调研 | 新建调研目标后，网页实时看到每一步，最后出一页带来源的报告；换 3 家公司都行 | 2 |
| F2 | 断点续跑 | 任务运行中重启 worker 容器，任务从断点继续，已完成的步骤不重跑 | 3 |
| F3 | 定时盯岗位 | 定时目标按计划触发，已推过的岗位不重复 | 3 |
| F4 | 主动通知 | 有新结果收到邮件；没有新结果不发 | 3 |
| F5 | 审批 | 不可撤销动作出现在审批页；未批准一定不执行；审计日志可查 | 4 |
| F6 | 记忆 | 在记忆页改偏好，下一次任务的行为跟着变 | 4 |
| F7 | 评测 | 一条命令跑完 15 个任务并输出六个指标 | 5 |

## 评测（阶段 5）

15 个固定任务：5 个调研、5 个盯岗位、3 个断点恢复、2 个注入攻击。

指标：任务完成率、断点恢复成功率（目标 100%）、审批拦截率（目标 100%）、通知准确率、单任务成本、单任务步数。
