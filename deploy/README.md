# 上线清单

阶段 1 的任务 4 使用。这里只列步骤和每一步的目的。具体命令由教练在那时按你的服务器和域名写出来，你自己在服务器上敲。

教练不登录服务器，不接触密码和私钥。

## 上线前要决定的事（写进 `coach/designs/stage1-deploy.md`）

| 决定 | 建议 | 原因 |
| --- | --- | --- |
| 服务器地区 | 香港或海外节点 | 境内服务器绑定域名对外提供网站服务需要先备案，耗时按周计。买之前向服务商确认当前规定 |
| 配置 | 2 核 4G 起 | 接口、数据库、Redis、worker、beat 同时运行 |
| 系统 | Ubuntu 长期支持版 | 资料最多 |
| 域名 | 任意注册商，挑便宜的后缀 | 只是学习和演示用 |
| 模型服务 | 确认服务器所在地区能访问 | 不能访问就换一家，只改环境变量 |

## 步骤

| 序号 | 做什么 | 目的 | 学到的概念 |
| --- | --- | --- | --- |
| 1 | 买服务器，用密钥而不是密码登录 | 有一台一直开着的机器 | SSH |
| 2 | 新建普通用户，关闭 root 密码登录 | 基本的安全 | 最小权限 |
| 3 | 防火墙只放行 22、80、443 | 数据库和 Redis 不暴露给公网 | 端口、防火墙 |
| 4 | 买域名，加一条 A 记录指向服务器地址 | 用名字访问 | DNS |
| 5 | 安装 Docker | 运行容器 | Docker |
| 6 | 把仓库拉到服务器 | 拿到代码 | |
| 7 | 在服务器上手动创建 `backend/.env` | 生产配置和密钥。`SECRET_KEY` 用随机长串，数据库密码换掉 | 环境变量 |
| 8 | 用生产配置的 compose 启动后端 | 接口、数据库、Redis、worker、beat 一起起来 | Compose |
| 9 | 执行数据库迁移 | 建表 | 迁移 |
| 10 | 构建前端，产物放到固定目录 | 得到静态文件 | 构建 |
| 11 | 安装 Caddy，按 `Caddyfile.example` 写配置 | 分流前端和接口，自动申请证书 | 反向代理、HTTPS |
| 12 | 用手机流量访问域名，走一遍注册登录 | 验收 | |
| 13 | 备份一次数据库 | 确认备份命令可用 | 备份 |

## 以后每次更新版本

1. 本地分支开 PR，CI 绿了合并。
2. 服务器上拉最新代码。
3. 重新构建并启动容器。
4. 有迁移就执行迁移。
5. 前端有改动就重新构建。
6. 打开线上地址确认。

做熟之后，阶段 5 可以让教练把这几步写成一个脚本。脚手架里的 `backend/scripts/deploy.sh` 是现成的起点，先把里面的旧项目名清掉。

## 参考

脚手架自带的 `backend/部署文档.md` 写了 compose 的三种启动方式、迁移、备份和排查命令。它推荐用系统 Nginx 做反向代理；本项目换成 Caddy，理由见 `docs/DECISIONS.md` 的 D008。
